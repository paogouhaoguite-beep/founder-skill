# Social Publication QA

Use this when a DTC merchant needs a social content release review with exact-payload claim, permission, disclosure, accessibility and destination checks

## Merchant inputs

Exact final post/media version; channel/account; merchant facts; rights; disclosures; destination; current platform restrictions; requested publication time.

Separate supplied facts, observed evidence, assumptions and unavailable information. Request only missing inputs that change the decision; a partial evidence set supports a partial result, not invented measurements.

## Tools and fallback

Read supplied CSV, screenshots, page text or documents with available file tools. A browser or authorized read-only connector can verify current pages and provider documentation. No named commercial service, host registry or script is required. Without live access, use dated exports and label the access window; do not imply a live check. Verify current provider-specific formats and policies before implementing a platform change.

## Procedure

1. Review one immutable content version and its intended account, placement and time; edits to caption/media/CTA restart affected checks.

2. Check factual claims and hook/payoff alignment, including visual implications, offer deadlines, stock and price. A creative style score cannot offset a false claim.

3. Verify exact rights for every third-party asset and required material-connection disclosure for the specific use.

4. Check readable text, captions/alt guidance, crop safety, destination continuity and current format requirements. Mark unavailable video or rendering checks unresolved.

5. Reject manipulative engagement rings and misleading incentives; preserve genuine questions and honest requests for feedback. Keep platform folklore separate from documented restrictions.

6. Deliver a pass/revise/unresolved checklist and the exact approved payload for human review. Publication status requires actual post evidence, not an approval label.

## Deliverable

A social content release review with exact-payload claim, permission, disclosure, accessibility and destination checks. This gates the assembled account-specific post payload, timing and live offer, including owned content with no creator contract; it does not accept a creator invoice or contractual delivery.

Include input provenance and observation dates beside affected rows. Explain the decision and the uncertainty it depends on; preserve exclusions and unresolved rows so another operator can reproduce the result.

## Execution scope

Prepare the analysis and reviewable artifacts within the requested scope. Sending messages, publishing, changing audiences or budgets, signing terms and editing live store settings require authorization for that action. A proposed change is not a completed action; report completion only from provider or page readback. Do not copy credentials or customer contact details into reports.
