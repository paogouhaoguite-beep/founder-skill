# Video Search Readiness

Use this when a DTC merchant needs a product-video search readiness brief with watch-page context, truthful metadata, chapters and access checks.

## Merchant inputs

Video asset/transcript; hosting page; thumbnail; title/description; rights; chapters/timestamps; actual page markup and crawl access.

Separate supplied facts, observed evidence, assumptions and unavailable information. Request only missing inputs that change the decision; a partial evidence set supports a partial result, not invented measurements.

## Tools and fallback

Read supplied CSV, screenshots, page text or documents with available file tools. A browser or authorized read-only connector can verify current pages and provider documentation. No named commercial service, host registry or script is required. Without live access, use dated exports and label the access window; do not imply a live check. Verify current provider-specific formats and policies before implementing a platform change.

## Procedure

1. Distinguish a dedicated watch page from a product page with supplementary video; the search task and expected indexing behavior differ.

2. Ensure the title and description describe the actual demonstration, product and viewing purpose. Avoid clickbait or keyword repetition that misstates content.

3. Check that video and thumbnail are accessible and that essential context exists as readable text; transcripts should reflect the media rather than invented dialogue.

4. Map valid video metadata, duration, publication date and chapters to the real asset. Do not claim structured data guarantees a video result.

5. Review thumbnail clarity and chapter boundaries against actual playback; verify platform-specific metadata limits at implementation time.

6. Deliver a video/page evidence checklist with exact metadata proposals and indexing observation plan. Separate uploaded, crawlable and observed-in-search states.

## Deliverable

A product-video search readiness brief with watch-page context, truthful metadata, chapters and access checks.

Include input provenance and observation dates beside affected rows. Explain the decision and the uncertainty it depends on; preserve exclusions and unresolved rows so another operator can reproduce the result.

## Execution scope

Prepare the analysis and reviewable artifacts within the requested scope. Sending messages, publishing, changing audiences or budgets, signing terms and editing live store settings require authorization for that action. A proposed change is not a completed action; report completion only from provider or page readback. Do not copy credentials or customer contact details into reports.
