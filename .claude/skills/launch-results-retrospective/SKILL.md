# Launch Results Retrospective

Use this when a DTC merchant needs a launch retrospective with receipt-qualified channel outcomes, feedback themes, sustained-demand checks and next-cycle decisions.

## Merchant inputs

Dated launch targets; actual publication/send receipts; comparable channel analytics; order truth; launch feedback; observation windows and cost.

Separate supplied facts, observed evidence, assumptions and unavailable information. Request only missing inputs that change the decision; a partial evidence set supports a partial result, not invented measurements.

## Tools and fallback

Read supplied CSV, screenshots, page text or documents with available file tools. A browser or authorized read-only connector can verify current pages and provider documentation. No named commercial service, host registry or script is required. Without live access, use dated exports and label the access window; do not imply a live check. Verify current provider-specific formats and policies before implementing a platform change.

## Procedure

1. Reconcile which launch actions actually occurred and when; keep partial or unknown outcomes visible before judging performance.

2. Compare predeclared targets with actuals in the same windows and attribution basis. Label reconstructed targets and separate platform reach from store orders.

3. Measure initial spike, sustained visits and owned-audience capture independently. Later repeat purchase needs a mature observation window rather than a launch-day estimate.

4. Cluster feedback by underlying need, count unique contributors and preserve representative quotes. Separate prevalence from severity and route product decisions to owners.

5. Investigate the largest material miss with an evidence-backed chain of explanations. Keep platform-algorithm stories as hypotheses and compare against a relevant baseline.

6. Issue keep/change/stop recommendations with effort, owner and next read date. Turn resolved feedback into factual follow-up drafts; do not announce an improvement before it exists.

## Deliverable

A launch retrospective with receipt-qualified channel outcomes, feedback themes, sustained-demand checks and next-cycle decisions.

Include input provenance and observation dates beside affected rows. Explain the decision and the uncertainty it depends on; preserve exclusions and unresolved rows so another operator can reproduce the result.

## Execution scope

Prepare the analysis and reviewable artifacts within the requested scope. Sending messages, publishing, changing audiences or budgets, signing terms and editing live store settings require authorization for that action. A proposed change is not a completed action; report completion only from provider or page readback. Do not copy credentials or customer contact details into reports.
