# Brand Extension Review

Use this when a DTC merchant needs a brand-extension decision memo with evidence-backed adjacency, architecture options and staged validation.

## Merchant inputs

Core brand promise; existing buyer evidence; proposed category/line; capability and quality constraints; price tier; channel effects; investment and risks.

Separate supplied facts, observed evidence, assumptions and unavailable information. Request only missing inputs that change the decision; a partial evidence set supports a partial result, not invented measurements.

## Tools and fallback

Read supplied CSV, screenshots, page text or documents with available file tools. A browser or authorized read-only connector can verify current pages and provider documentation. No named commercial service, host registry or script is required. Without live access, use dated exports and label the access window; do not imply a live check. Verify current provider-specific formats and policies before implementing a platform change.

## Procedure

1. List the brand associations and advantages supported by actual customer or operating evidence. Separate durable capabilities from one successful ad or unsupported loyalty claims.

2. Map the proposed extension to a real buyer occasion and identify why trust in the core product would transfer; distinguish adjacency from mere logo reuse.

3. Check manufacturing/service credibility, quality level, price tier and distribution conflicts. A profitable extension can still contradict the core promise.

4. Compare master-brand, endorsed sub-brand or separate-brand options using clarity, operating cost and customer confusion, not an invented moat score.

5. Define a small evidence-gathering pilot with success and harm signals, including core-customer reaction and operational capability.

6. Return a go/test/hold decision with assumptions, required proof and reversible investment stages. No brand extension is declared defensible simply because it is first-party data or a community.

## Deliverable

A brand-extension decision memo with evidence-backed adjacency, architecture options and staged validation.

Include input provenance and observation dates beside affected rows. Explain the decision and the uncertainty it depends on; preserve exclusions and unresolved rows so another operator can reproduce the result.

Prepare the analysis and reviewable artifacts within the requested scope. Sending messages, publishing, changing audiences or budgets, signing terms and editing live store settings require authorization for that action. A proposed change is not a completed action; report completion only from provider or page readback. Do not copy credentials or customer contact details into reports.
