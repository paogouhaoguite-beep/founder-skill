# Creator Content Acceptance

Use this when a DTC merchant needs a creator asset acceptance report with timestamped brief checks, claim/rights blockers and actionable revision feedback

## Merchant inputs

Final creator asset or transcript; approved brief/version; product evidence; offer and destination; disclosures; usage rights; requested platforms.

Separate supplied facts, observed evidence, assumptions and unavailable information. Request only missing inputs that change the decision; a partial evidence set supports a partial result, not invented measurements.

## Tools and fallback

Read supplied CSV, screenshots, page text or documents with available file tools. A browser or authorized read-only connector can verify current pages and provider documentation. No named commercial service, host registry or script is required. Without live access, use dated exports and label the access window; do not imply a live check. Verify current provider-specific formats and policies before implementing a platform change.

## Procedure

1. Bind review to the exact asset version, brief and destination. A later edit requires rechecking affected claims, captions and disclosures.

2. Compare the delivered work with contracted product, angle, format, required shots and CTA. Separate missing mandatory requirements from subjective style preferences.

3. Check spoken, visual and text claims against evidence; a visual implication can overstate performance even when the caption is accurate.

4. Review disclosure visibility, third-party assets and rights for the intended placement. Unknown permission is an unresolved item, not a numeric deduction that can be averaged away.

5. Inspect hook/payoff alignment, legible captions, audible speech, product demonstration and destination continuity. Use actual playback or mark video-only checks unverified when only a transcript exists.

6. Return accept, revise or unresolved with timestamped findings and actionable feedback. Approval applies only to that asset and use scope; publishing requires its own authorization.

## Deliverable

A creator asset acceptance report with timestamped brief checks, claim/rights blockers and actionable revision feedback. This accepts a commissioned asset against its brief and contracted delivery; it does not release an assembled scheduled social post.

Include input provenance and observation dates beside affected rows. Explain the decision and the uncertainty it depends on; preserve exclusions and unresolved rows so another operator can reproduce the result.

## Execution scope

Prepare the analysis and reviewable artifacts within the requested scope. Sending messages, publishing, changing audiences or budgets, signing terms and editing live store settings require authorization for that action. A proposed change is not a completed action; report completion only from provider or page readback. Do not copy credentials or customer contact details into reports.
