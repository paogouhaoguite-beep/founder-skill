# Community Program Design

Use this when a DTC merchant needs a member-value community plan with rules evidence, participation rituals, moderation roles and context-specific reply drafts.

## Merchant inputs

Member need beyond shopping; community rules; existing participation; team capacity; brand affiliation; examples of local conversations and permitted promotional activity.

Separate supplied facts, observed evidence, assumptions and unavailable information. Request only missing inputs that change the decision; a partial evidence set supports a partial result, not invented measurements.

## Tools and fallback

Read supplied CSV, screenshots, page text or documents with available file tools. A browser or authorized read-only connector can verify current pages and provider documentation. No named commercial service, host registry or script is required. Without live access, use dated exports and label the access window; do not imply a live check. Verify current provider-specific formats and policies before implementing a platform change.

## Procedure

1. Define a member-value promise such as repair help, category learning or peer use cases. Select the community space by audience evidence and moderation capacity, not channel popularity.

2. Read current rules and norms from official rules plus dated examples. Separate explicit requirements from observed tone and unverified algorithm folklore.

3. Plan a small set of useful recurring rituals and an onboarding path. For an existing external community, contribute relevant help before proposing any brand activity; disclose affiliation where material.

4. When drafting a reply, read the original post and existing replies, answer the actual question and add a distinct useful detail. Do not fabricate personal experience or use covert recommendation scripts.

5. Specify moderation ownership, escalation and the route for order-specific private support. Treat member retention, useful answers and response coverage separately from list growth.

6. Define an observation period and continued-investment criteria using merchant capacity and community value. Do not use synchronized engagement, automated unsolicited replies or universal posting ratios.

## Deliverable

A member-value community plan with rules evidence, participation rituals, moderation roles and context-specific reply drafts.

Include input provenance and observation dates beside affected rows. Explain the decision and the uncertainty it depends on; preserve exclusions and unresolved rows so another operator can reproduce the result.

## Execution scope

Prepare the analysis and reviewable artifacts within the requested scope. Sending messages, publishing, changing audiences or budgets, signing terms and editing live store settings require authorization for that action. A proposed change is not a completed action; report completion only from provider or page readback. Do not copy credentials or customer contact details into reports.
