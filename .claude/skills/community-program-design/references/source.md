## Specific changes

A member-value community plan with rules evidence, participation rituals, moderation roles and context-specific reply drafts.

- Define a member-value promise such as repair help, category learning or peer use cases. Select the community space by audience evidence and moderation capacity, not channel popularity.
- Read current rules and norms from official rules plus dated examples. Separate explicit requirements from observed tone and unverified algorithm folklore.
- Plan a small set of useful recurring rituals and an onboarding path. For an existing external community, contribute relevant help before proposing any brand activity; disclose affiliation where material.
- When drafting a reply, read the original post and existing replies, answer the actual question and add a distinct useful detail. Do not fabricate personal experience or use covert recommendation scripts.
- Specify moderation ownership, escalation and the route for order-specific private support. Treat member retention, useful answers and response coverage separately from list growth.
- Define an observation period and continued-investment criteria using merchant capacity and community value. Do not use synchronized engagement, automated unsolicited replies or universal posting ratios.

Removed upstream mandatory registries, benchmark gates, mutable connector paths and software-only assumptions. Replaced them with merchant-supplied artifacts and explicitly labeled decisions. Kept task-specific method; replaced fixed industry targets with declared merchant constraints. Synthetic cases below are authored for this adaptation, not claimed customer outcomes.
