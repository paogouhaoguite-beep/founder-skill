# Ad HTML Creative Draft

Use this when a DTC merchant needs a self-contained HTML creative draft, exact canvas/export specifications, claim-and-asset ledger and variant/QA table with observed versus untested status.

## Merchant inputs

Approved headline/offer and substantiation, brand fonts/colors, owned product image/logo files and usage rights, target placement dimensions and safe area, destination and desired single-variable variants.

Separate supplied facts, observed evidence, assumptions and unavailable information. Request only missing inputs that change the decision; a partial evidence set supports a partial result, not invented measurements.

## Tools and fallback

Read supplied CSV, screenshots, page text or documents with available file tools. A browser or authorized read-only connector can verify current pages and provider documentation. No named commercial service, host registry or script is required. Without live access, use dated exports and label the access window; do not imply a live check. Verify current provider-specific formats and policies before implementing a platform change.

## Procedure

1. Freeze offer, claims and one creative hypothesis. Separate the concept from its rendered asset; an HTML file is not a PNG upload. Verify current placement requirements from supplied specifications or official documentation before final export.

2. Choose text-first, product-image or branded-proof composition from the brief. Product-image variants require an actual authorized product asset; missing imagery produces a labeled placeholder draft, never an invented product photo. Meme/native styles must not impersonate independent testimony or use unlicensed media.

3. Build a standalone HTML canvas with explicit width/height, predictable box sizing, local/system fonts, adequate padding and one hierarchy: message, supporting fact, CTA. Use supplied brand values rather than a universal house palette. Reference only permitted local assets; do not embed trackers or pull unknown remote scripts.

4. Fit text by actual rendered wrapping and safe areas, not only a character-count formula. Keep offer qualifications legible; do not shrink disclosures to make an unfit headline work. Maintain an HTML text alternative for review even when final delivery will be an image.

5. If a browser/screenshot tool is available, capture the intended canvas after fonts/assets load; inspect clipping, missing images, product fidelity, contrast and exact dimensions. Otherwise deliver HTML plus an explicitly unverified render checklist. Never call a file uploaded or platform-approved from a local screenshot.

6. For variants change one meaningful element and retain IDs linking concept/text/asset/export. Return actual files, previews when available and a review table; publication, ad upload and spend require separate authorization.

## Deliverable

A self-contained HTML creative draft, exact canvas/export specifications, claim-and-asset ledger and variant/QA table with observed versus untested status.

Include input provenance and observation dates beside affected rows. Explain the decision and the uncertainty it depends on; preserve exclusions and unresolved rows so another operator can reproduce the result.

## Execution scope

Prepare the analysis and reviewable artifacts within the requested scope. Sending messages, publishing, changing audiences or budgets, signing terms and editing live store settings require authorization for that action. A proposed change is not a completed action; report completion only from provider or page readback. Do not copy credentials or customer contact details into reports.
