# 程序化 SEO 规划器

> 来自 [ShopChief](https://shopchief.ai/?utm_source=programmatic-seo-planner&utm_medium=agent_skill&utm_campaign=commerce_skills&utm_content=skill_header) · 面向独立站与 DTC 卖家的 AI 运营工作流。可独立使用，无需 ShopChief 账号。

## 定位

本技能按顺序回答两个问题:(1) 这个程序化打法对这个店铺值不值得建;(2) 若值得,页面模板具体长什么样、什么条件会让它在放量时变成薄内容。全程执行的核心规则:**关键词+变量不算独特内容。** 一个 URL 只有在向购物者交付了"用户无法通过改另一个页面的一个变量就还原出"的信息时,才配被索引——对店铺而言,通常意味着真实的商品目录数据(规格、库存、价格、适配、评论)或真实的策展内容。

交付物是带模板的决策文档,不是生成出来的页面本身。

## 边界

- 对单个选定主题做深度选题与编辑 brief → `seo-content-research`。
- 已存在页面的技术问题(索引、canonical、性能) → `site-seo-audit`。
- 编辑型内容策略的 Pillar-Cluster 地图 → `seo-content-research`。

## 适用页面模式(DTC 店铺语境)

| 模式 | 示例 | 数据来源 |
| --- | --- | --- |
| 产品×属性 | "{产品} {材质}" / "{产品} {尺码} {颜色}" | 商品目录属性 |
| 品牌×品类集合页 | "{品牌} {品类}" 集合页 | 目录 + 品牌维度 |
| 用途/场景落地页 | "{品类} for {活动/场景}" | 目录属性 + 策展 |
| 对比页 | "{产品 A} vs {产品 B}" | 规格表、评论数据 |
| 买家指南 | "怎么选{品类}"、"{品类} 尺码指南" | 目录属性 + 品类知识 |

不在范围内:本地服务模式("{城市}×{服务}")、目录式 B2B 模式、内容站打法——本技能只规划 DTC 店铺的页面模式。

## 必备输入

| 输入 | 必需性 | 缺省处理 |
| --- | --- | --- |
| 关键词模式(如"{品类} for {使用场景}") | 必需 | 追问 |
| 支撑变量的目录/属性数据集(来源、字段清单、样例行) | 必需 | 追问;没有数据集时结论不得高于"Pilot、低信心" |
| 平台(默认 Shopify) | 建议 | 声明假设 |
| 竞品 pSEO 页面样例 URL(若有) | 可选 | 改用 web 搜索取 SERP 证据 |

## 必须流程

1. **模式验证。** 把模式分解为头部词×变量。从商品目录枚举现实组合数(不是属性的笛卡尔积)。证据:对最多 20 个采样组合做低价 DataForSEO 查询(DataForSEO Labs Google 关键词创意 看需求形态,用户需要时用 DataForSEO Labs Google 批量关键词难度 看难度)。每条指标记录市场与日期;缺失值写 `N/A`。
2. **商品目录数据集审计。** 每个属性/字段评估:完整度(多少商品有值)、唯一性(取值在组合之间是否真的不同)、新鲜度(价格/库存波动)、以及取值是否会改变页面给购物者的信息。逐字段输出 通过/警告/不通过。注意 Shopify 特性:变体级属性、metafields 作为属性来源、集合筛选的可用性。
3. **独特性断言。** 对每类 URL,说明哪些内容是组合特有的(规格对比、库存、适配建议),哪些是模板套话。若组合特有部分只剩"换一个属性值",该类就是 **noindex** 或 **合并** 候选。
4. **结论:Go / Pilot / No-Go + 信心等级**(高/中/低),由 (1)-(3) 支撑。参考门槛:Go = 有足量组合带真实需求 且 目录数据能产出真正不同的页面;Pilot = 需求可见但目录质量未验证;No-Go = 薄内容风险或需求可忽略。
5. **逐类 URL 决策:** 生成 / 合并(并入集合页或产品父页)/ noindex / canonical 指向父页,附理由。
6. **模板集**(每个"生成"类):URL 模式、Title、H1、正文模块清单(哪些模块由目录数据驱动、哪些静态)、FAQ(问题必须能从目录数据或真实买家提问推导,不得凭空编造)、Schema 类型(JSON-LD:按需用 Product、ItemList、FAQPage、BreadcrumbList)。变量以 `{占位符}` 表示。
7. **放量计划:** 试点集(10-20 页)、成功指标、放量条件、停止条件(索引率、互动阈值、人工处置风险)。
8. **质量门槛断言。** 每个试点页在放量前必须通过的、可检验的具体陈述,例如"每页 ≥ 3 个目录特有数据点"、"任意两页正文重合 ≤ 60%"。这些是待验证的断言,不是编造的实测值。

## 输出格式

1. **结论块** — Go / Pilot / No-Go + 信心等级 + 三条支撑发现。
2. **组合表** — 采样组合 | 需求证据 | 难度(如已查)| 决策。
3. **目录审计表** — 属性/字段 | 完整度 | 唯一性 | 新鲜度 | 判定。
4. **模板集** — 每个生成类一份。
5. **放量计划** — 试点 → 放量 → 停止条件。
6. **质量门槛断言。**

## 失败处理

- 未提供目录数据集:结论封顶"Pilot、低信心",并说明需要哪些目录字段。
- 关键词端点返回空或不可用:需求列标 `N/A`,降级为 web 搜索的 SERP 证据,并在结论中说明降级。
- 已配置的 DataForSEO 工具不可用:如实说明,不得编造搜索量或难度值。
- 本技能不生成实际页面内容,那属于内容生产环节。
