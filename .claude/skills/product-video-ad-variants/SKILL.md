# Product Video Ad Variants

Produce actual controlled video variants for a merchant's creative test. This owns asset-level changes and comparable exports; it does not predict an ad winner from render quality.

## Define the test and fixed facts

Collect the approved base video/assets, factual script, audience/placement, target duration/ratio, exact offer terms and the requested variant count/budget. Identify a testable creative question and the one primary variable: opening wording/shot, edit rhythm, product angle or CTA treatment. If the user requests broader concepts, label them concept alternatives rather than a controlled single-variable comparison.

Keep price, discount, eligibility, dates/timezone, product/SKU, landing destination and factual qualifications fixed unless the specified variable legitimately changes them. Do not invent savings, reviews or customer results to make a hook stronger. Preserve authentic demonstration order and evidence.

## Execute the variants

Build a variant matrix before production: variant ID, hypothesis, changed interval, changed text/asset and fixed remainder. Reuse the approved footage and assets where practical; generate only the genuinely missing scene within authorized tool/count/budget scope. Read [production execution](references/production.md), inspect actual capabilities, await generation tasks and render every requested version through the available editor.

Use separate versioned filenames and a consistent export profile. Compare the changed sections and also verify the unchanged remainder, captions, offer and destination. Audio transitions and music alignment may need variant-specific adjustment without changing the factual message. A caption or crop change that hides an essential qualifier is a failed variant.

Never report `winner`, improved ROAS, stronger conversion or a proven hook from these files alone. State the test hypothesis and the actual production differences. Deployment, campaign budget and measurement setup are separate from making the video files unless explicitly requested.

## Deliver

Return actual video files, preview/contact sheet where useful, variant matrix, final scripts, source/task map and verified metadata. Mark unresolved or rejected versions individually rather than reporting the whole batch complete. Without rendering tools, deliver full per-variant timelines and scripts marked `not rendered`, with no claimed test result.
